# Simbia Captions

A native macOS editor for vertical UGC video ads: captions with animated styles, titles, shots on a multi-track
timeline, colour, lipstick and keying, sound, and export — plus `simbia`, the same engine as a command-line tool
for scripts and AI assistants. Interface in English, Russian and French.

- **What it does:** [docs/FEATURES.md](docs/FEATURES.md) (English) · [docs/FEATURES.ru.md](docs/FEATURES.ru.md) (Russian)
- **Requirements:** macOS 26, Xcode 26 / Swift 6 toolchain; `ffmpeg` (Homebrew) for audio analysis and some exports.
- **Build:** `./build-app.sh` → `../Simbia Captions.app` and `../bin/simbia`. `swift build` alone to check that it compiles.
- **Brand settings stay on your machine:** `~/Library/Application Support/Simbia Captions/Brand.json`, e.g.
  `{"name": "Acme", "key": "acme", "houseMusic": "House bed.wav"}` (the dictionary's first word, the product's name in
  the footage index's tags, the music level a new bed is matched to). Brand pictures go in `Assets/Brand/`, which git ignores.

## Проект `.simbia` и синхронизация с Claude

Проект — JSON-файл (`Sources/SimbiaCore/Project.swift`): холст, сетка долей, шоты
(клип, `in`, push in/out, затемнение), звук (голос, музыка с дакингом, громкость,
фейды), MG-сцены (папки PNG-кадров), субтитры (слова с таймингами и акцентами,
стиль `s1…s10` или `legacy`), заголовки `T1…T5`, громкость финала. У каждого поля
есть значение по умолчанию; пути абсолютные или относительно файла проекта.

Синхронизация (`ProjectSync.swift`): правка в программе записывается через полсекунды
(атомарно, `revision + 1`, `savedBy: "app"`); файл проверяется дважды в секунду, и
изменение, сделанное снаружи (Claude), подхватывается одним шагом отмены — ⌘Z
возвращает как было. Сравнение смысловое: переформатированный, но тот же проект не
перезаписывается. Пишущий снаружи должен писать атомарно (временный файл + rename).
Программа никогда не пишет поверх файла, изменённого снаружи после её последнего чтения
или записи: сначала загружает его (своя правка остаётся в истории). Повторный `open`
уже открытого проекта — та же перезагрузка, без сброса истории и позиции. Перед
выходом и перед открытием другого проекта несохранённая правка записывается.

Окно одно, проект в нём один: двойной щелчок по другому проекту или меню «Проекты» (проекты
из той же папки и недавние) открывает его в этом же окне. Сохраняется всё и сразу: правка
записывается через 0,3 с, при переключении на другую программу, перед открытием другого
проекта и при выходе (недописанный текст в поле сначала фиксируется). Видео без файла проекта
после распознавания само становится проектом в `~/Library/Application Support/Simbia Captions/Projects`
(есть в «Недавних»); повторное открытие того же видео продолжает его, а не распознаёт заново.

Субтитр (`chunk`) может нести `"paragraph": true` — начало абзаца, и `"emphasis": true` —
акцент всей реплики в классических стилях (оба поля пишутся только когда true). Если ни
один субтитр не помечен, абзацы идут по предложениям (после `.`, `!`, `?`, `…`) и паузам
от 0,7 с. Перегруппировка при смене семейства стилей идёт внутри абзацев. Отсутствующие
`id` получают позиционные (`s3`, `c12`), а не случайные.

### Дорожка «Наложение»: хромакей и трансформ (`layers`)

Видео в `layers` — те же шоты, что и в `shots`. Без новых полей слой, пока играет, закрывает
картинку под собой, как раньше. С `chromaKey` (включённым) или `transform` (не единичным) он
ложится поверх картинки с прозрачностью — как Keyer + Transform у присоединённого клипа в
Final Cut. Работает одинаково в превью, `simbia frame` и `simbia export`; в программе
ползунки и перетаскивание видео по картинке видны сразу, без пересборки превью (как цвет).
Все `overlays` (PNG-сцены) и титры рисуются поверх слоёв; звук слоя не играет.

```json
"layers": [{ "id": "v1", "start": 0, "end": 15, "src": ".../grok121.mp4", "in": 0,
  "chromaKey": { "strength": 0.5, "shrink": 1, "soften": 1, "spill": 0.9 },
  "transform": { "scale": 0.5185, "x": -290, "y": 462 } }]
```

`transform` — `scale` (1 = как шот во весь кадр, с его кадрированием), `x`, `y` — сдвиг в
stage px (1080 по ширине, y вниз), `rotation` — поворот в градусах по часовой вокруг центра
бокса (пишется только когда не 0). Масштаб — от центра кадра, потом сдвиг: на кадре
1080 × 1920 бокс видео x = 540·(1 − scale) + x … + 1080·scale, y = 960·(1 − scale) + y …
+ 1920·scale, затем поворот. В программе выбранный слой показывает на картинке рамку с ручкой
в углу (та же, что у эмодзи на заголовке): тянуть видео — сдвиг, ручку — масштаб и поворот
(0° и 90° прилипают, ⌘ — без прилипания), двойной клик — обратно в центр. Кадрирование и трансформ делаются одним масштабированием (картинка
пересчитывается один раз). Пример выше — Grok-дубль 400 × 736 шириной 560 px, левый край −30,
низ на нижнем крае кадра.

`chromaKey` — шаги Keyer, как эталонный Python-кеер v3, на собственных пикселях видео — до
кадрирования и масштаба (дёшево; «Края» и «Мягкость» — в пикселях исходника). Поля необязательные:
1. цвет ключа K — `color` (`"#RRGGBB"`, пипетка; его наибольший канал задаёт экран); без
   `color` — у клипа один раз: поканальная медиана пикселей, где зелёный на 0.25 больше
   красного и синего (0.12, если таких меньше 1 %), в каждом 24-м кадре первых 15 с — в фоне,
   кэш по файлу; `simbia frame`/`export` ждут замер, превью до него берёт среднее экрана кадра;
2. маска (`strength` 0…1): d = (g − max(r, b)) / то же у K; alpha = 1 − smoothstep(low, high, d),
   low/high = 0.73·(1 − strength) ∓ 0.185 (0.18 / 0.55 при 0.5);
3. инструменты маски, только по альфе: `shrink` px (−3…3; 1 = минимум 3 × 3, меньше 0 — расширить),
   `soften` px (0…3; 1 = среднее 3 × 3); край кадра продолжается наружу, как `np.pad(edge)`;
4. края: C − 0.6·(1 − alpha)·K, без деления на alpha;
5. зелень на всём персонаже (`spill` 0…1): g − spill·max(0, g − (r + b)/2).

`"on": false` выключает ключ, сохраняя настройки. Цвет шота и фильтр проекта — после ключа.
«Показать маску» в окне слоя — альфа белым по чёрному только в окне просмотра (в проект и
экспорт не попадает). Ядро — Core Image-ядра на Metal (`Sources/SimbiaCore/Keyer.swift`).
С `keyed/123.mov`, `124.mov` (key121.py v3) совпадает: альфа ±0.0001, цвет края ±1/255.

### Скорость клипа (`speed`)

У шота (и видео в `layers`) и у звукового клипа есть `speed` — секунды исходника на секунду
монтажа: 2 — вдвое быстрее, 0.5 — вдвое медленнее; пишется только когда не 1, старые файлы
читаются как раньше. Место и длина на монтаже не меняются (`start`/`end`, у звука `duration`),
клип берёт `длина · speed` исходника от `in`: момент t монтажа = `in + (t − start)·speed`
исходника (`Shot.source(at:)`, `AudioClip.source(at:)`). Так считают превью, `simbia frame`,
`export`, ключи кадрирования (`keys[].t` — время исходника), переходы (запас кадров за склейкой
тоже ×speed), размытие движения (соседний кадр — на кадр монтажа назад, `speed / fps` исходника),
миниатюры, разрезы, подрезки и подписи по голосу.

```json
"shots": [{ "id": "s5", "start": 9.24, "end": 12.48, "src": ".../_fin_row2L8.mp4", "in": 0.8, "speed": 2.222 }],
"audio": [{ "id": "a7", "role": "voice", "src": ".../_fin_row2L8.mp4", "start": 9.24, "in": 0.8, "duration": 3.24, "speed": 2.222 }]
```

Звук другой скорости играется с тем же тоном: кусок исходника один раз растягивается
`AVAudioUnitTimePitch` офлайн в кэш `~/Library/Caches/SimbiaCaptions/speed` и кладётся в микс как есть
(`Sources/SimbiaCore/SpeedRender.swift`; растяжение звука средствами самой композиции иногда давало
тихий клип, обрыв микса или зависание). Не хватает исходника — картинка растягивается до конца шота
(медленнее заданного), звук кончается раньше. В окне шота — «Скорость»: ползунок ×0.25…×4, ×1/×1.5/×2/×3
и точное число; собственный звук шота (тот же файл, в синхроне) получает ту же скорость.

Замедленный шот (и растянутый из-за короткого исходника), у которого кадры исходника иначе
показывались бы повторно (`скорость · fps исходника < fps монтажа`), получает промежуточные кадры
по оптическому потоку, как «Optical Flow» в Premiere/Resolve (`Sources/SimbiaCore/Tween.swift`).
Сам шот лежит на своей дорожке, а тот же исходник на кадр вперёд — на дорожке `ahead` (её же
использует размытие движения). Из готовой композиции считываются точные карты времени обеих
дорожек (`segments[].timeMapping`, с её округлением до 1/600 с) и времена кадров файла (sample cursor,
без декодирования). Поэтому компоновщик знает, какие два кадра пришли и где между ними момент монтажа.
Поток Apple Vision считается в обе стороны: на экспорте на половине ширины кадра и с высокой точностью,
в превью — быстрее. Оба кадра сдвигаются к этому моменту (Super SloMo) и смешиваются. Точку, которую
другой кадр не видит (из-за перекрытия), берём из того кадра, где она видна. На кадре исходника
и в переходах кадр остаётся как есть. Видео в `layers` пока не дорисовывается.

### Аудиобиблиотека

Щелчок по названию дорожки «Музыка» (или «Другой трек…» в окне музыкального клипа) открывает на всё окно треки из
`_ASSETS/MUSIC` над проектом, со всеми подпапками (`MusicLibrary.swift`, `MusicLibraryView.swift`): слева папки,
справа карточки — название, папка, длина, волна, громкость (LUFS всего файла, ffmpeg `ebur128`, как в
`_SCRATCH/music1111/music.py`; считается один раз на файл, кэш `~/Library/Caches/SimbiaCaptions/music.json`) и где трек
уже стоит музыкой в проектах этой папки («свободен» / «в 504, 517»; «Сначала свободные» поднимает неиспользованные).
Клик — послушать (плеер монтажа встаёт на паузу), двойной клик или «Поставить» — заменить: у каждого клипа с `role`
music меняются `src` и `label`, остаются `start`, `in`, `duration`, затухания и `duck`, а `gain` подгоняется к прежней
громкости: `gain · 10^((LUFS старого − LUFS нового)/20)` (в файле — до тысячных, как все gain). Нет музыки — сначала
вопрос, потом трек на весь ролик на уровне домашнего трека (`houseMusic` в Brand.json) с gain 0.025, затухание 1.15 с. Короче нужного — оранжевая
строка на карточке. Одна отмена на замену.

### Стекло под сценой (`overlays[].glass`)

У сцены кита (`overlays[]`) может быть стекло: под её кадром — то, что уже нарисовано (видео, затемнение под
заголовком, сцены раньше неё), как через настоящее матовое стекло.

```json
"overlays": [{ "id": "m1", "src": ".../frames/end_glass", "start": 24.3, "label": "end_glass",
  "glass": { "mask": ".../frames/end_glass_mask", "blur": 30, "refraction": 1 } }]
```

`mask` — папка PNG-кадров той же сцены, где альфа = форма стекла (кадр в кадр со сценой, со сдвигом сцены);
`blur` — радиус размытия в px при ширине 1080 (30); `refraction` — изгиб у края: 1 = 25 px у самой кромки,
сходит на нет ~35 px внутрь, в середине только размытие (как край толстой линзы); 0 — плоское стекло.
Кадр: картинка размывается, чуть светлее (+0.04) и насыщеннее (×1.15), у края берётся чуть глубже из стекла
(по направлению мягкой маски — ядро Core Image, `Sources/SimbiaCore/Glass.swift`), режется по альфе маски,
сверху — кадр сцены. Превью и `export` одинаково. Без `glass` сцена рисуется как раньше (побайтово).
Под сильным размытием изгиб виден только на крупных формах; на 10–15 px он заметен явно.

Правый щелчок по сцене на дорожке «Графика» → «Заменить на…»: папки рядом с ней с тем же началом до первого «_»
(`end_glass` → `end_seal`, `end_kinetic`…), без масок `…_mask` и без `end_tapbelow` (Богдан убрал её из выбора).
Меняются только `src` и `label`; время, длина и место остаются. Если рядом есть папка `<имя>_mask`, ставится `glass`
с ней (размытие и изгиб прежнего стекла сохраняются), иначе стекло снимается. ⌘Z — одним шагом.

## Нативный движок = web-версии стилей

Стили 11 и 12 «Обычные» (Plain, одна строка / две строки) — только в программе, без web-версии: белый Montserrat 800 с тонкой тёмной обводкой и мягкой тенью, фраза появляется целиком (лёгкое проявление 0,12 с), выделенное слово просто в 1,22 раза крупнее. В Highlighter (2 и 7) выделенное слово с 2026-10-13 белое с той же обводкой, что и остальные (web-версии обновлены так же).
Во вкладке «Субтитры» над карточками — настройки для всего ролика и любого стиля: «ВСЕ ЗАГЛАВНЫЕ», «Курсив» (у прямых шрифтов наклон 12°), «Акцентные слова» (выключено — все слова одинаковые) и для стилей 11/12 — «Появление»: Pop (как субтитры прежних роликов: 70% → 104% → 100% с уходящим размытием за 0,2 с), По словам, Снизу, Плавно. В `.simbia` это `captions.uppercase`, `captions.italic`, `captions.accents: false`, `captions.entrance` (пишутся, только когда заданы). Карточки стилей показывают эти настройки; у «Классики» заглавные и курсив — её собственные (`look`). Картинки слов кэшируются с этими настройками в ключе (`CaptionOptions.look`), иначе после переключения превью показывало бы прежние.
Заголовки T6 «Текст» (белые заглавные Montserrat 800 с подстрочником, как «7 REASONS» / «#1 REASON» прежних роликов) и T7 «Плашка» (чёрные заглавные на белой таблетке, как «BUY 1 GET 1 FREE») появляются «попом» и уходят затуханием 0,3 с; «|» — новая строка. Эмодзи в заголовках рисуются цветными (как есть, без заливки); строка из одних эмодзи в T7 идёт крупнее и без таблетки — например «😴|1. Toning it down» ставит эмодзи над плашкой, как в референсе VSL «3 things». Анимированные эмодзи на заголовке (`stickers` в TitleItem: emoji, x, y от центра кадра, size, rotation): в окне заголовка блок «Эмодзи» — паки Noto / Telegram (`emojiPack` проекта; лежат в Application Support/Simbia Captions/Emoji/<пак>/<коды>.webp|gif|png + index.json, можно ссылкой на папку библиотеки), «+ Эмодзи» — сетка всех эмодзи пака с поиском, размер и поворот выбранного; на видео эмодзи тянется мышью, кружок в углу вращает и масштабирует (⌘ — без прилипания к 0/90°), двойной клик — на место, ⌫ — удалить. Эмодзи, которого нет в паке, рисуется обычным.
T8 — карточка отзыва Trustpilot, как в моушн-ките прежних роликов (×1,2; Inter): фото, имя, дата, пять зелёных звёзд, текст до 5 строк с «…», See more, Company replied, Useful/Share. Влетает сбоку снизу с поворотом и размытием (0,45 с), звёзды выскакивают по одной, медленный наезд, затухание 0,3 с; низ карточки не заходит на субтитры. В `.simbia`: `text` — отзыв, `kicker` — «имя|дата», `image` — путь к фото (нет — инициалы на пастельном круге). T9 «Коллаж отзывов» (сцена comments кита: до 4 карточек 640 px веером, влетают через 0,42 с, общий наезд 5%) и T10 «Слайдер отзывов» (сцена reviews_carousel: белая панель «Reviews shaping this summary», карточки одной высоты, сдвиг на карточку каждые 0,9 с после нажатия стрелки) — `reviews` в `.simbia` (фото полными путями). На таймлайне всё это и сцены кита (`overlays`, PNG-кадры 30 к/с) — на дорожке «Графика»: блоки двигаются, ⌫ удаляет; у сцены кита правый край тянется (и «Длина» ±0,5 с в её окне, «Длина сцены» — вернуть свою): `duration` в `overlays` — сцена появляется как сделана, стоит на последнем полном кадре сколько нужно и уходит своим затуханием (короче — затухание раньше; кадр ожидания — последний не ниже 97 % непрозрачности, `MotionLibrary.holdFrame`); без `duration` — ровно как раньше; щелчок по заголовку, графике или сцене открывает окно настроек над таймлайном (в правой панели настроек нет — так хочет Богдан). Во вкладке «Графика»: кнопки «Коллаж отзывов» / «Слайдер отзывов», лента «Сцены из кита» (папка `RENDER_KIT/motion/frames` — откуда сцены проекта или над проектом) и список отзывов; при выбранном коллаже/слайдере щелчок по отзыву добавляет или убирает его. Карточка T8 добавляется из того же списка: список отзывов из `_ASSETS/TRUSTPILOT/reviews.json` (фото в `av/`; ищется над проектом, рядом с индексом клипов или в выбранной папке), клик — карточка на 4,5 с у плейхеда (или замена отзыва на выбранной), «Свой отзыв» — пустая карточка; в её настройках имя, дата, фото из `av/` и «В библиотеку» (дописывает reviews.json).


Стили субтитров 1–10 и заголовки T1–T5 рисуются нативно (`Sources/SimbiaCore/Overlay/`)
правило в правило как web-эталон `Reference/overlay_ref.html`: те же файлы шрифтов,
`em`, flex-раскладка с выравниванием по базовой линии, `line-height: normal`
(сбрасывается шортхендом `font:`), ключевые кадры с `cubic-bezier` по интервалам,
порядок отрисовки обводки и тени как в Chromium, SVG-фильтры `feTurbulence` +
`feDisplacementMap` по эталонному коду спецификации. Сверка:

```
python Reference/ref_frames.py <project.simbia> <t,...> <ref-prefix> [--style sN] [--no-titles]
.build/release/simbia overlay <project.simbia> <t,...> <nat-prefix> [--style sN] [--no-titles]
python Reference/compare.py <ref-prefix> <nat-prefix> <t,...> <sheet.png> [--crop y0:y1]
```

Измерено: CG-тень = 2 × CSS-радиус; слова и заголовки — спрайты (один рендер, дальше
только трансформ/прозрачность/размытие); проявление цвета заголовков — смесь двух
закэшированных крайних состояний (точно, т.к. всё линейно по цвету).

Кадр не 9:16 (4:5, 1:1, 16:9) получает сцену 1080×1920, вписанную по высоте и по центру,
так что субтитры и заголовки остаются в кадре (превью и экспорт одинаково).

Монтаж (`Composition.swift`, `Compositor.swift`, `Audio.swift`) повторяет рендеры V5:
заполнение кадра, push in/out как `zoompan`, dim, размытие под заголовками (радиусы
подогнаны к ffmpeg `gblur`), MG поверх, дакинг музыки — порт `sidechaincompress`,
моно-источники на −3 дБ (как апмикс ffmpeg). Экспорт (`Export.swift`): AVFoundation
+ параллельный компоситор, затем `loudnorm` до −14 LUFS (видео копируется, звук дополняется
тишиной до длины ролика). Инструкции компоситора всегда покрывают всю шкалу без щелей;
недоступный клип (перемещён, удалён, без картинки) в превью показывается чёрным с
уведомлением, а экспорт с ним останавливается с перечнем файлов. ffmpeg берётся первый
найденный из `Exporter.ffmpegCandidates` (программа передаёт проверенный запуском).

## Проверка, словарь, паузы, подбор кадров

Логика — в `SimbiaCore` (общая для программы и консоли):

- `Checks.swift` — проверка перед экспортом: наложения, повторы Whisper (одинаковые подряд субтитры,
  слово 4+ раз), написание по словарю, текст ужат больше чем до 70 % (`CaptionStyle.textScale`),
  субтитр не по голосу, смена в 1–3 кадрах от склейки, промежуток короче 0,3 с, меньше 0,3 с (0,6 с
  у двухстрочных) или быстрее 25 знаков/с, заголовок короче 2 с, склейка внутри шота, нет файла. У каждого вида своё
  исправление (`fixing(_:only:)`), «исправить всё» проходит все виды дважды.
- `Voice.swift` — громкость голоса по 10 мс на шкале ролика и порог речи (тише голоса на 28 дБ, но на
  8 дБ выше шума). Субтитр, появившийся в тишине, переносится туда, где голос начинается (Whisper
  растягивает слово на паузу перед ним); конец — через 0,3 с после голоса, если дальше пауза или
  тишина длиннее 0,9 с. Край на склейке остаётся на ней, если голос не дальше 4 кадров.
- `Glossary.swift` — `~/Library/Application Support/Simbia Captions/Glossary.txt` (по слову в строке,
  без файла — имя бренда из `Brand.json`): подсказка whisper (`--prompt … --carry-initial-prompt`) и исправление
  похожих слов (расстояние правки ≤ 2, притяжательное 's сохраняется).
- `Pauses.swift` — паузы ищутся по звуку голоса; вырезание: кадр говорящего и голос — встык с
  фейдами 20 мс, другие шоты укорачиваются, музыка играет дальше, субтитры/заголовки сдвигаются.
- `SourceCuts.swift` — склейки внутри клипа-источника: каждый кадр сравнивается с предыдущим (яркость по
  сетке 24×24 и гистограмма); склейка — скачок на одном кадре (сетка ≥ 0,12 и в 2,5 раза больше соседних
  кадров, гистограмма ≥ 0,2), плавная смена света — нет. Смотрятся только куски, которые показывают шоты
  (кроме кадра говорящего — его склейки свои), по четыре сразу; найденное хранится в
  `~/Library/Caches/Simbia Captions/source-cuts.json`. Если в куске есть склейка, клип просматривается
  целиком, и «Склейка внутри шота» сдвигает начало на ближайший чистый участок нужной длины; если такого
  нет — исправления нет, замечание просит заменить клип.
- `Footage.swift` — индекс библиотеки (`_ASSETS/_index/clips/*.json`, `usage.json`): слова → теги
  `best_for` (англ. и рус.), без вшитых титров и «avoid», амбассадоры раньше ИИ, неиспользованные раньше.

После распознавания программа сама исправляет написание и ставит субтитры по голосу без мигания.
В шапке рядом с «Экспорт» — значок проверки; «Экспорт» сначала показывает замечания.

## Редактирование субтитров

Выделение: щелчок — один субтитр, ⇧-щелчок — диапазон от якоря, ⌘-щелчок — добавить или
убрать, ⌘A — все, Esc — снова один. Клавиши (по положению, работают и в русской раскладке):
S — разрезать субтитр под курсором воспроизведения, M — объединить выделенные (или со
следующим), J / K / L — назад (на 1 с, если плеер не умеет играть назад), стоп, вперёд (1×, 2×,
4×), ↩ — новый абзац с выделенного субтитра или соединить его абзац с предыдущим,
⌫ — удалить выделенные субтитры (или выбранный заголовок). Над таймлайном одна панель: «Текст»,
«Субтитры», «Заголовки», «Классика» (отдельного инспектора нет). Во вкладке «Текст» весь текст по
абзацам; слово увеличивается под курсором, а щелчок по нему открывает окно инструментов: правка
слова, акцент, разрыв (с этого слова начнётся новый субтитр), абзац, удалить слово, тайминг
субтитра, объединение. Номер абзаца выделяет его целиком; при выделении нескольких субтитров над
текстом появляется полоса действий. Настройки заголовка — в окне по щелчку на него в таймлайне; настройки шота открываются щелчком по шоту в таймлайне. Правый щелчок по субтитру
(в таймлайне и в тексте) — меню с теми же действиями. У выделенного субтитра в таймлайне слова
стоят по своим временам между разделителями — тянуть разделитель значит двигать начало слова (по
кадрам); в окне слова «Звучит» — начало и конец слова ±1 кадр. В «Тексте» — поиск с заменой (тайминг
слов сохраняется) и словарь; над таймлайном «Вырезать паузы»; в окне шота — «Подобрать из
библиотеки». «Классика» — ряд «Стили · Появление · Угасание · Настройки» и карточки, как у субтитров.

Галерея футажей: в окне шота «Вся библиотека…» открывает на всё окно все пригодные моменты индекса `_ASSETS/_index` (сегменты клипов) по категориям — наносит помаду, тюбик в камеру, губы крупно/результат, улыбка, говорит в камеру, сухие губы/недовольна, другие помады/ящик, продукт отдельно, b-roll; фильтры «Амбассадоры / AI / Сток и продукт», поиск по имени и описанию. Начальная категория — по тексту над шотом (`FootageIndex.category(for:)`). Щелчок — момент играет справа по кругу, двойной щелчок или «Поставить в шот» — клип и начало ставятся в шот; Esc закрывает. Отсеяно: `avoid`, вшитый текст, конкуренты/готовые ролики, «DO NOT USE», ssstik и **розовый наконечник** (домашнее правило: стик продукта только с белым/прозрачным наконечником — по описаниям индекса `FootageIndex.pinkTip`). «Скрыть из библиотеки» (розовый наконечник / плохой кадр / не наш продукт) пишет `_index/hidden.json` — такие моменты пропадают из галереи и подбора.

Субтитры не двигаются сами (автоподъём над графикой Богдан отменил 2026-10-13) — их ставят перетаскиванием. Любой субтитр, заголовок, графику или сцену можно перетащить прямо на видео (двойной щелчок — обратно на место; в окне заголовка/сцены — «На место»): смещение в пикселях сцены 1080 × 1920 пишется в `x`/`y` у чанка, заголовка или `overlays` и учитывается в экспорте. Сцена кита — часть видео: пока её тянешь, двигается пунктирная рамка, картинка обновляется после отпускания.

Пока на таймлайне тянут край шота или двигают момент клипа, в окне просмотра — кадры, которые останутся на краях, как в Final Cut (`EdgePreview.swift`): белая ручка слева — новый первый кадр, справа — новый последний; золотая (сдвиг склейки) — последний кадр до склейки и первый после, рядом; полоска сверху шота (другой момент клипа) — первый и последний кадр шота, рядом. То же для левого и правого края видео на дорожке «Наложение». Подписи — «первый кадр · 33.75 с» (секунды файла). Кадры из самого файла (отражённый шот — отражённым, без кадрирования и цвета); грузится только последний запрошенный. Отпустили — снова обычный кадр под плейхедом. У сцен на «Графике» кадров клипа нет — там ничего не показывается.

«Выровнять все заголовки по этому» — правый щелчок (или щелчок двумя пальцами) по заголовку на видео или на таймлайне, ⇧⌘A или «Правка → Выровнять все заголовки по выбранному»: всем остальным `titles[]` один раз ставится `y` выбранного (смещение от своего места; у заголовков одного стиля это одна высота). `x`, текст, время и стиль не меняются, связи между заголовками не остаётся — дальше каждый двигается сам; ⌘Z возвращает всё одним шагом.

Звук в таймлайне — две дорожки: «Голос» и «Музыка» (с провалами под голосом). Щелчок по клипу — он выделен и открыто окно громкости: ползунок −45…+12 dB (до упора влево — без звука, около 0 — «как записано»), «Без звука»; громкость не 0 dB видна в конце дорожки. Это `gain` клипа; плеер пересобирается, когда ползунок отпущен.
Каждый клип — рамка: перетащить — сдвинуть (`start`), перетащить край — обрезать (левый край двигает и `in`), края и сдвиг липнут к плейхеду; S режет выделенный клип по плейхеду (второй кусок продолжает тот же файл, затухания остаются на внешних краях), ⌫ удаляет. Тяга по пустой дорожке — перемотка. Контур звука читается из файла один раз и режется по клипу.
Пересборка плеера после правки шота или заголовка занимает ~0,15 с: анализ голоса и автоматизация
громкости музыки кэшируются (`DuckEnvelope`, `MixCache`; у звуковых дорожек постоянные id). Каждая дорожка
начинается с громкости своего клипа (`setVolume` в 0): AVFoundation включает рампы на ~18 мс позже.
Уровни звука в превью (громкость, затухания и их дуга, дакинг) кладёт на каждый сэмпл наш собственный tap на
каждой звуковой дорожке (`LevelTap`, MTAudioProcessingTap) — той же кривой `Volume.level`, по которой экспорт строит
рампы громкости. Рампы самого AVPlayer меняли уровень порциями и щёлкали там, где затухание начинается или кончается;
экспорт (`AVAssetReaderAudioMixOutput`) читал те же рампы чисто и остался как был. Проверка — `simbia playtap
<проект> <out.wav> [с] [длина] [--retarget <другой.simbia> <с>]`: проигрывает превью (без звука) и пишет, что
отдают tap'ы; на синусах совпадает с `simbia audio` до сэмпла (разница ≤ 0.0001, у музыки ≤ 0.001 — допуск рамп).
Время буфера tap до эффектов сообщает своё (после эффектов — на буфер раньше); первый буфер после старта или перемотки
без времени — тишина предвключения. Правка только уровней (`Project.mixFree` равен) плеер не пересобирает: новые
уровни уходят в tap'ы играющего item (`Job.remix` → `LevelTap.retarget`), каждый уровень переходит к новому за 20 мс.

Позиция воспроизведения (`PlayClock`) не публикуется в SwiftUI: курсор таймлайна и оверлей —
слои Core Animation, оверлей перерисовывается дисплейной ссылкой с частотой кадров ролика,
поэтому во время воспроизведения окно не перекладывается 20 раз в секунду.

Речь распознаёт сам Mac, на устройстве (`SimbiaCore/MacSpeech.swift`: SpeechTranscriber, для остальных
языков DictationTranscriber; недостающий язык скачивается сам). Внешний бинарник один — `ffmpeg`;
берётся первый, который реально запускается (сломанная установка Homebrew остаётся исполняемой, но падает в dyld):
`/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`, затем `/opt/homebrew/bin`, `/usr/local/bin`, `/opt/local/bin`.

## Заметки по libass

Проверено рендерингом кадров, а не по документации:

- Цвета стиля — `&HAABBGGRR`, `AA=00` означает непрозрачный.
- `\an5\pos(x,y)` центрирует и текст, и `\p1`-фигуру ровно в этой точке,
  поэтому подложка и текст анимируются как одно целое.
- Путь `\p1` должен использовать неотрицательные координаты: libass считает
  габарит фигуры от начала координат.
- Несколько непересекающихся `\t()` в одном событии работают как ключевые кадры.
- Обводка не масштабируется вместе с `\fscx/\fscy` — её нужно тянуть через `\bord`.
- `\alpha` задаёт все четыре альфа-канала, поэтому идёт до `\3a`/`\4a`.
- `\t()` не анимирует `\pos`, `\move`, `\org`, `\fad`.

Файл субтитров передаётся во `-vf` голым именем, а рабочей директорией процесса
ставится `Work/`: значение фильтра разбирается ffmpeg дважды, и экранированный
апостроф этого не переживает.
